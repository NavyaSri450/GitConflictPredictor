# Stage 5 feature engineering review

The API contract still contains 18 numerical fields. Review of the existing definitions and collector found only five with a stable, repository-independent calculation available before the simulated merge. Those five now define an **exploratory baseline model input subset**. No API fields were removed, renamed, or relaxed.

| Currently unused API feature | Could local Git alone measure it? | Required definition/evidence before implementation | Decision |
| --- | --- | --- | --- |
| `commit_severity` | Git provides diffs and commit metadata, but not a severity concept. | A declared severity formula, normalization, and source/target scope. A size proxy would be a different feature. | Unavailable; do not infer. |
| `developer_commits` | `git log` can count commits by author/committer identity. | Which developer, identity normalization, author vs committer, branch scope, and lookback window. Names/emails also require privacy review. | Unavailable; no actor is specified. |
| `developer_conflicts` | Not from a single Git history without recorded attempted-merge outcomes and actor attribution. | Time-ordered prior merge labels, developer identity mapping, and a window ending before the current snapshot. | Unavailable; no historical outcome source. |
| `activity_score` | Commit dates can be counted, but no score can be calculated without arbitrary choices. | Actor/branch scope, lookback interval, normalization, and treatment of bursts/inactivity. | Unavailable; score definition is missing. |
| `import_count` | Not generically. Git stores blobs, not language syntax trees. | Supported languages, parser/version, whether to count added imports or all imports, generated/vendor files, and rename rules. | Unavailable; no language policy. |
| `dependency_conflicts` | Dependency files can be located in Git, but conflict meaning is not defined by their diffs alone. | Supported ecosystems/manifests and a definition distinct from the current overall merge-conflict label. Historical counts need prior labeled events. | Unavailable; do not proxy from the current merge outcome. |
| `coverage` | Git does not store coverage measurements. | A coverage artifact tied to an exact pre-merge commit, test command/tool/version, and collection environment. Running tests during collection is intentionally avoided. | Unavailable unless supplied as verified pre-merge metadata. |
| `branch_conflicts` | Not from commit graph metadata alone. | Prior attempted-merge labels associated with a branch, time window, and event-counting rules. | Unavailable; no history store. |
| `branch_risk_score` | Requires historical outcomes and a formula. | Past-only rate/score definition, denominator/smoothing, window, and fold-local calculation to prevent leakage. | Unavailable; no formula. |
| `pattern_frequency` | Not until “pattern” has a stable meaning. | Versioned pattern taxonomy, matcher/version, and time cutoff. | Unavailable; no taxonomy. |
| `pattern_conflicts` | Requires both patterns and prior merge outcomes. | Versioned matcher plus historical labels, with current/future outcomes excluded. | Unavailable; no taxonomy or history. |
| `dependency_risk` | Not as a scalar without a formula and dependency evidence. | Ecosystem scope, risk calculation, historical or advisory snapshot date, and pre-merge cutoff. | Unavailable; no definition or source. |
| `pattern_risk` | Not as a scalar without a formula and pattern evidence. | Versioned pattern taxonomy, risk calculation, and past-only training-fold history. | Unavailable; no definition or history. |

## Measurement review and safe future definitions

The existing API meanings are preserved. The notes below distinguish a Git primitive that could supply raw evidence from an actual feature definition. A command producing metadata does not by itself make that metadata a valid input. If a future definition is adopted, its cutoff must be the selected pre-merge snapshot (the source and target commit IDs recorded on the row); any historical aggregate must be calculated from events strictly earlier than that cutoff, and recalculated inside each training fold. This collector records simulated merge outcomes at collection time, not historical merge-event timestamps, so its newly collected labels cannot safely serve as historical rates for the same snapshot.

| Feature | Possible local evidence / calculation if later specified | Time window and availability | Why it is not collected now |
| --- | --- | --- | --- |
| `commit_severity` | `git diff --numstat <base> <source>` gives added/deleted text lines; `git diff --name-status -z <base> <source>` gives changed paths/statuses. A score would require an explicit formula, path weights, and normalization. | Candidate diff is available pre-merge; a history-based normalizer must use earlier commits only. | No severity formula exists. Substituting a change-size score would change the documented feature meaning. |
| `developer_commits` | `git log --format=%H --author=<identity> <since>..<snapshot> -- <scope>` could count commits after deciding how identity and scope are defined. Commit author metadata is available without reading messages. | Needs an explicit duration ending at the snapshot, author-versus-committer choice, and identity mapping. | No developer/actor is part of the request, nor is a window or scope defined. Names/emails are unnecessary personal data for default collection. |
| `developer_conflicts` | Requires a separate event ledger of past attempted merges, actor IDs, and binary outcomes; count only eligible prior rows after defining actor and merge direction. | Fixed lookback ending strictly before the current snapshot; grouped splits and fold-local aggregation are required. | Git commit history does not encode attempted merge failures or their actor. Never use the current row's label. |
| `activity_score` | `git log --format=%ct <range>` can provide commit timestamps for a defined branch/author/scope; an activity score then needs a published formula (for example, a count or decay, not an assumed score). | A named rolling duration ending at the prediction snapshot; all included commits must already exist then. | Neither scope, formula, nor interval is specified. |
| `import_count` | `git diff --name-only -z <base> <source>` can enumerate paths, but counting imports requires a language parser and a declared rule (added import lines, all imports in changed files, or another precise count). | Candidate source diff is pre-merge; parse only source tip (or diff) using a pinned parser/language policy. | Git itself has no syntax semantics; arbitrary text search would miscount languages, comments, and generated/vendor code. |
| `dependency_conflicts` | Git can identify changed manifests via `git diff --name-only -z <base> <source>`. A meaningful count requires parsing supported lockfiles and defining a dependency-conflict event independently of the overall merge target. | For historical frequency, use only previously recorded dependency-specific merge outcomes before the snapshot. | Changed dependency files do not imply a dependency conflict. Deriving this from the current merge conflict label leaks the target. |
| `coverage` | Requires an externally produced coverage report whose provenance binds exact commit, tool/version, test configuration, and measurement time to the selected source/target state. Git history alone cannot produce coverage. | Artifact must predate the simulated merge and refer to the exact candidate commit; collector must not execute repository tests. | No artifact or reproducible test environment is supplied. |
| `branch_conflicts` | Requires a historical merge-event ledger keyed by stable branch identity and outcome; count events by a declared rule. Refs from `git branch --contains <commit>` alone do not tell whether previous merges conflicted. | Fixed pre-snapshot lookback; exclude current/future events and compute aggregates within training folds. | Commit graph has no record of failed merge attempts, and branch names are mutable. |
| `branch_risk_score` | Could be a smoothed historical conflict rate only after defining denominator, smoothing, branch key, and handling of branches with no attempts. | Historical outcomes strictly before the candidate snapshot; fold-local calculation to avoid target leakage. | No formula or historical event source. |
| `pattern_frequency` | Requires a versioned extractor over prior changes/outcomes. Git could supply candidate diffs and paths, but the pattern matcher is not a Git primitive. | Matcher must inspect only information existing at the snapshot; frequency window and history cutoff must be fixed. | “Pattern” has no taxonomy or matching definition. |
| `pattern_conflicts` | Requires the same versioned pattern matcher plus a ledger linking each prior pattern observation to a merge outcome. | Count only labeled events strictly before the current row; aggregate fold-locally. | No taxonomy or labeled history; current target cannot be used. |
| `dependency_risk` | Requires a defined dependency inventory and risk formula (including source/version of advisory or other evidence); candidate manifests can be obtained from the source tree but this project does not parse or contact advisory services. | Evidence snapshot and advisory database version must be dated no later than the prediction point; no remote access by default. | No ecosystem scope, formula, dependency inventory, or offline advisory snapshot is supplied. |
| `pattern_risk` | Requires a versioned pattern taxonomy, a specified risk statistic, and historical outcomes associated with detected patterns. | Only prior examples; fit aggregate values within each training fold and preserve the pattern-data cutoff. | No taxonomy, formula, or reliable history exists. |

## Reduced baseline strategy

The trainer now uses exactly these five directly measurable inputs:

1. `files_changed`: unique incoming-source paths from `git diff --name-only base source`.
2. `lines_added`: textual additions from `git diff --numstat base source`; binary files contribute no line count.
3. `avg_files_per_commit`: mean first-parent changed-path count across incoming-source commits after base.
4. `branch_commits`: target first-parent commit count after base.
5. `branch_files_changed`: unique target paths from `git diff --name-only base target`.

They describe change volume and branch divergence using only the selected pre-merge commit pair. They are a reasonable **baseline experiment**, not a claim that five structural values contain enough information for dependable prediction. Correlation between the counts is possible and held-out repository evaluation is required.

The other 13 columns remain part of the raw/processed dataset and API contract and remain blank when unmeasured. Validation reports their missingness; the baseline excludes them explicitly. The model bundle records both `model_features` (five) and `api_feature_names` (18). The local ML scorer accepts the five documented model inputs; the FastAPI endpoint remains HTTP 501 and has not been connected to this scorer. Do not put placeholder zeros into the 13 unused API fields to make a prediction request.
